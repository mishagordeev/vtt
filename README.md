# Poison Press VTT

Виртуальный стол (VTT) для настольной игры «Вторые»: чат, кубики и листы персонажей.
Next.js 15 (App Router) + TypeScript + Tailwind CSS 4, деплой на Vercel.

Живёт в базе «Луна»: `02_Projects/Poison_Press/vtt/`. Материалы книги, заметки ведущего
и официальный бланк персонажа — рядом, в `../Vtorye/`.

## Что умеет

- **Комнаты по ссылке.** Мастер создаёт стол, получает код и ссылку вида `/r/A7K2QM`.
- **Вход по имени.** При первом входе игрок вводит имя, оно сохраняется в `localStorage`
  (общий ключ `pp:name` и ключ на комнату `pp:room:<КОД>:name`), дальше вход автоматический.
  Кнопка «сменить» в шапке сбрасывает запомненное имя.
- **Чат справа.** Лента сообщений, под ней широкое поле ввода, под ним кубики.
- **Кубики.** d4, d6, d8, d10, d12, d20, d100, модификаторы `+1`/`−1`, «Очистить».
  Кнопки вставляют формулу (`1d20+3`) прямо в текст поля; повторный клик по тому же
  кубику увеличивает количество (`1d6` → `2d6`).
- **Броски считает сервер.** Из текста сообщения вытаскиваются формулы вида `1d20+5`,
  `2d6`, `d20`, `4d6kh3` (keep highest / `kl` — keep lowest), результат с отдельными
  костями и итогом показывается в чате.
- **Карта Кас-Хатара на «Столе».** Слева от чата — карта города; поверх неё видны
  курсоры игроков и мастера с именами (у мастера — ♛). Кисть и ластик работают мышью
  и пальцем, линии и курсоры синхронизируются через комнату; очистить всё может мастер.
- **Вкладка «Персонажи».** Слева открывается лист выбранного персонажа, справа — список
  всех листов комнаты. Лист разбит на вкладки: «Основное», «Характеристики»,
  «Происхождение», «Особенности», «Навыки», «Знания», «Снаряжение», «Заметки». Правка —
  у владельца и мастера; остальные смотрят лист в режиме чтения.
- **Каталоги с галочками.** Особенности, изъяны, навыки и знания выбираются списками с
  прокруткой и короткими описаниями; у навыков и знаний — ранг I–V и минимум характеристики.
- **Генерация характеристик.** Три способа из книги: «Суровый жребий» (3d6 по порядку),
  «Раскладка» (3d6×7, худший отбросить) и «Героический жребий» (4d6 с отбросом меньшей).
- **Происхождение.** Шесть народов Кас-Хатара с модификаторами характеристик, языками и
  культурным кодом: один конкретный навык и два знания. Выбор сразу добавляет дары и их
  стартовое снаряжение в рюкзак; смена народа снимает старые.
- **Навыки и знания отдельно.** Недоступные по минимуму характеристики не показываются;
  у выбранных — ранг I–V и пометка «от происхождения». Каждый навык и знание даёт
  подобранный стартовый набор в рюкзак.
- **Снаряжение по слотам.** Каталог предметов с описаниями; лимит слотов равен Силе.
  В руках — 1 оружие + щит, 2 одноручных или 1 двуручное; доспех один и не занимает руки;
  не больше четырёх предметов без слотов. Предметы двигаются между руками и рюкзаком;
  всё, что не помещается в слоты, подсвечивается красным.
- **Монеты в рюкзаке.** Отдельного поля денег нет: монеты — строка инвентаря, 100 монет
  любого металла занимают 1 слот.
- **Портрет.** Загрузка jpg/png (и любого формата, который читает браузер), обрезка в круг
  с перетаскиванием и ползунком размера; в карточке — круг, по клику открывается полная
  картинка. Хранится в листе как сжатый data URL.

## Схема правил

Состав листа описан в одном файле — `lib/rules.ts`: характеристики, производные числа,
навыки и знания, особенности и изъяны, предметы, доспехи и щиты. Короткие описания для
каталогов — в `lib/notes.ts`. Форма и карточка строятся из этих массивов, поэтому под свою
редакцию правил достаточно поправить значения и формулы, не трогая компоненты.

Что уже сведено с «Книгой игрока» (`../Vtorye/ВТОРЫЕ_Книга_игрока.md`):

- **1.1, 1.5** — шесть характеристик 3–18, модификатор `(значение − 10) / 2`, три способа
  генерации, бонус испытаний +2/+3/+4, ОЗ `8 + Тел`, КБ `доспех + Ловкость (с пределом) + щит`.
- **1.2** — шесть происхождений: модификаторы, языки и культурный код из одного навыка и
  двух знаний; при выборе сразу выдаются стартовые наборы этих навыков и знаний.
- **1.3** — 25 особенностей и 15 изъянов с описаниями; на листе одна особенность и один изъян.
- **1.4.5** — стартовые наборы подобраны для всех 83 навыков и знаний и лежат в `STARTER_KITS`.
- **6.5–6.7** — 10 боевых навыков, 50 небоевых и 23 знания с минимумами, пометкой ★ и
  короткими описаниями; уточнения вроде «Язык: шуари» распознаются; недоступные по
  минимуму не показываются.
- **7.3–7.5** — 95 предметов плюс монеты: оружие, доспехи, щиты, свет и припасы; слоты,
  цены, описания, `twoHanded` для двуручного оружия.
- **1.4** — предыстории и мировоззрение не выбираются: это примеры и концепция из книги.
  Игрок сам отмечает навыки и знания, а монеты лежат в рюкзаке (100 шт. = 1 слот).

Если правило меняется в книге, синхронизируйте массивы и формулы в `lib/rules.ts`,
описания — в `lib/notes.ts`, и покройте изменение тестом в `tests/rules.test.mjs`.

Старый лист (Тело / Реакция / Разум / Воля / Эмпатия / Тень, Здоровье и Стресс)
читается по совместимости: ОЗ подхватывается из прежнего ресурса `health`, навыки —
из поля `level`, старые `money`, доспех и щит переносятся в монеты и инвентарь; при первом
сохранении лист переводится на новую схему.

## Локальный запуск

```bash
npm install
npm run dev
# http://localhost:3000
```

Проверки:

```bash
npm run typecheck   # tsc --noEmit
npm test            # node --test tests/dice.test.mjs tests/rules.test.mjs
npm run build       # production-сборка, как на Vercel
```

`npm test` импортирует `lib/dice.ts` и `lib/rules.ts` напрямую, поэтому нужен Node 22.18+
(встроенное стирание типов). На Vercel тесты не запускаются — только сборка.

Без переменных окружения комнаты живут в памяти процесса — удобно для разработки,
но данные пропадают при перезапуске и не делятся между инстансами.

## Хранилище и деплой на Vercel

На Vercel серверные функции не хранят состояние между вызовами, поэтому нужен Redis.
Поддерживается любой Upstash Redis (Vercel KV, Marketplace или нативный Upstash) —
достаточно REST-переменных, транспортные пакеты не нужны:

```
KV_REST_API_URL=...
KV_REST_API_TOKEN=...
# либо
UPSTASH_REDIS_REST_URL=...
UPSTASH_REDIS_REST_TOKEN=...
```

Порядок:

1. Импортируйте репозиторий в Vercel (Framework Preset определится как Next.js,
   команды сборки менять не нужно).
2. В проекте Vercel добавьте интеграцию Redis (Upstash) — переменные подставятся сами,
   либо добавьте их вручную в Settings → Environment Variables.
3. Задеплойте. Откройте корень сайта, нажмите «Создать комнату», скопируйте ссылку.

Без Redis приложение тоже поднимется, но на Vercel комнаты будут «пропадать» между
запросами — это режим для локальной разработки.

### Проверка хранилища

`GET /api/health` показывает, какой режим включён, и пингует Redis через REST:

```json
{
  "ok": true,
  "storage": { "mode": "redis", "reachable": true, "latencyMs": 42 },
  "checkedAt": 1793004098827
}
```

`mode: "memory"` — переменные окружения не подхватились; `reachable: false` — Redis
настроен, но не отвечает (эндпоинт отдаёт 503). Тот же статус виден в панели стола
строкой «Хранилище: Redis · N мс».

### Регион функций

Регион функций Vercel выбирается отдельно от региона базы: новый проект по умолчанию
собирается в `iad1` (Вашингтон), даже если база Upstash лежит во Франкфурте. Каждый
запрос к Redis тогда идёт через Атлантику (~100 мс). Чтобы этого избежать, выставьте
Settings → Functions → Function Region в регион базы (`fra1` для Frankfurt) и
передеплойте проект.

### Про обновление данных

Состояние комнаты лежит в одном ключе `poison-press:room:<КОД>` (JSON, TTL 30 дней).
Клиент опрашивает `/api/rooms/<КОД>/state` раз в 2 секунды на вкладке «Стол» (карта и
курсоры) и раз в 4 секунды на «Персонажах», только пока вкладка активна, и мгновенно
обновляется после своих действий. Присутствие обновляется «пульсом» раз в 30 секунд
(запись в хранилище не чаще раза в 20 секунд на игрока). Курсор на карте отправляется
не чаще раза в 1,2 секунды, поэтому активная карта — самая «дорогая» по записям часть
комнаты; для компании из 4–6 человек этого хватает, но при экономии запросов увеличьте
`POLL_INTERVAL`/`TABLE_POLL_INTERVAL` в `components/RoomScreen.tsx`. Линии карты хранятся
в том же JSON комнаты (до 200 линий по 600 точек), поэтому после сессии их можно очистить
кнопкой мастера.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/rooms` | создать комнату, вернуть код |
| GET | `/api/health` | режим хранилища (Redis/память), пинг Redis и задержка |
| GET | `/api/rooms/[code]/state?since=<seq>` | снимок комнаты и новые сообщения |
| POST | `/api/rooms/[code]/join` | вход/возврат игрока по имени |
| POST | `/api/rooms/[code]/heartbeat` | присутствие |
| POST | `/api/rooms/[code]/messages` | сообщение (бросок считается на сервере) |
| POST | `/api/rooms/[code]/characters` | создать персонажа |
| PATCH/DELETE | `/api/rooms/[code]/characters/[id]` | правка/удаление |

## Известные ограничения

- Нет авторизации: кто знает ссылку и имя — тот за столом. Имя и есть идентичность,
  поэтому под чужим именем можно войти (как в дружеском чате).
- Лимит груза и рук проверяется в интерфейсе; сервер нормализует данные, но не запрещает
  сохранение перегруза (нужно для переноса старых листов).
- Портрет хранится в листе как сжатый data URL (до ~260 КБ обрезанный и ~540 КБ полный);
  это увеличивает размер комнаты в Redis. Очень большие фото браузер сжимает сам.
- Опрос вместо WebSocket: задержка до ~4 секунд, зато деплой без внешних сервисов
  реального времени.
- Одновременные записи в Redis из разных инстансов не блокируются (блокировка только
  внутри процесса) — для стола на несколько человек этого достаточно.
