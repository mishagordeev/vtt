# Poison Press VTT

Виртуальный стол (VTT) для настольной игры «Вторые»: чат, кубики и листы персонажей.
Next.js 15 (App Router) + TypeScript + Tailwind CSS 4, деплой на Vercel.

Живёт в базе «Луна»: `02_Projects/Poison_Press/vtt/`. Материалы книги, заметки ведущего
и официальный бланк персонажа — рядом, в `../books/Vtorye/`.

## Что умеет

- **Комнаты по ссылке.** Мастер создаёт стол, получает код и ссылку вида `/r/A7K2QM`.
- **Вход по имени.** При первом входе игрок вводит имя, оно сохраняется в `localStorage`
  (общий ключ `pp:name` и ключ на комнату `pp:room:<КОД>:name`), дальше вход автоматический.
  Кнопка «сменить» в шапке сбрасывает запомненное имя.
- **Чат справа.** Лента сообщений, под ней широкое поле ввода, под ним кубики.
  Своё сообщение можно удалить наведением мыши; мастер удаляет любые, включая системные.
- **Кубики.** d4, d6, d8, d10, d12, d20, d100, модификаторы `+1`/`−1`, «Очистить».
  Левый клик добавляет кость (`1d20` → `2d20`), правый — убирает; разные кубики
  складываются в сумму `1d20+1d6`, а модификаторы сжимаются в один (`+1`, `+1`, `+1` → `+3`).
  Кнопки вставляют формулу прямо в текст поля.
- **Броски считает сервер.** Из текста сообщения вытаскиваются формулы вида `1d20+5`,
  `2d6`, `d20`, `4d6kh3` (keep highest / `kl` — keep lowest), результат с отдельными
  костями и итогом показывается в чате.
- **3d-кубики разлетаются по столу.** Новый бросок не собирается в панель: каждая кость
  влетает со своего края, кувыркается и падает в случайную точку стола. Тело гранёное —
  число граней соответствует типу (d4 треугольник, d8 октаэдр, d12 додекаэдр, d20 икосаэдр),
  d6 остаётся кубом с точками, d100 бросается двумя d10 (десятки и единицы). Цвет костей
  берётся из профиля бросившего. Внизу на 3 секунды появляется строка «формула = итог».
  Старые броски при загрузке и после перечитки ленты не проигрываются.
- **Карта Кас-Хатара на «Столе».** Слева от чата — карта города. Кисть и ластик работают
  мышью и пальцем, линии и метки синхронизируются через комнату; очистить всё может мастер.
  Клик по карте — круглая метка цветом профиля: толстая, расходится широко, живёт 3 секунды.
  Кнопка «Подписи» включает русские названия районов поверх карты (перевод из «Вторых»),
  в углу карты — масштаб: 1 гекс ≈ 6 миль ≈ 10 км. Под картой — код комнаты, ссылка,
  состояние хранилища и список игроков; списка листов и памятки по кубикам на «Столе» больше нет.
- **Профили игроков.** Клик по игроку в списке «За столом» открывает профиль: имя, личный
  цвет (он же цвет метки на карте и костей) и привязанные листы персонажей. Привязка
  двусторонняя: лист видит своих игроков, игрок — свои листы; один лист можно назначить
  нескольким игрокам. Игрок правит свой профиль, мастер — любой; мастер может убрать игрока
  из-за стола. Переименование сразу обновляет листы, чат, музыку и рисунки.
- **Экспорт листов.** В списке персонажей есть «Экспорт»: JSON (один лист или все сразу),
  самостоятельный HTML и PDF через окно печати — «Сохранить как PDF».
- **Версия в шапке.** `v0.4.6` рядом с названием: берётся из `package.json` через
  `next.config.ts` и поднимается при каждом коммите, который меняет VTT.
- **Музыка: плейлист над чатом, добавление слева.** Треки живут в правой колонке над чатом;
  ссылку YouTube добавляет любой игрок во вкладке «Музыка». Запуск, пауза и «Играть все» /
  «Стоп все» — только у мастера. У мастера есть громкость каждого трека (слышно всем),
  у каждого игрока — своя общая громкость, по умолчанию 50%, хранится в браузере.
  Итоговый звук = личный уровень × громкость трека. Треки продолжают играть при переходе
  на карту или к персонажам; если браузер блокирует автозапуск — кнопка «Разрешить звук».
- **Тема — старый пергамент.** Бежевая палитра в духе Baldur's Gate и Icewind Dale:
  тёплый фон, коричневые чернила, старое золото вместо неона, антиква в тексте.
  Переопределены палитры Tailwind (`zinc` → пергамент, `emerald` → золото) в `app/globals.css`.
- **Свой хостинг.** Проект не привязан к Vercel: есть `Dockerfile`, `docker-compose.yml`,
  готовый systemd-юнит `deploy/vtt.service` (расчёт на `/srv/vtt`) и инструкция `HOSTING.md`
  (Nginx, systemd, варианты Redis, что делать с картинками).
- **Дебаг-панель мастера внизу страницы.** Свёрнутая строка и раскрывающиеся подробности:
  сколько запросов ушло в базу, сколько байт получено и отправлено (за сессию и за день),
  последний запрос и время ответа, разбивка по адресам, режим хранилища из `/api/health`
  (Redis/память, хост, пинг, право записи), размер комнаты. Счётчики лежат в `localStorage`,
  поэтому видно трафик и за прошлые визиты.
- **Обновление только по действиям.** Фонового опроса по таймеру нет: комната читается
  после своих правок (сообщение, лист, карта, музыка, вход), при возврате на вкладку,
  при переключении вкладки и по кнопке `⟳`. Присутствие обновляется теми же действиями,
  без «пульса».
- **Вкладка «Персонажи».** Слева открывается лист выбранного персонажа, справа — список
  всех листов комнаты. Лист разбит на вкладки: «Основное», «Характеристики»,
  «Происхождение», «Особенности», «Навыки», «Знания», «Снаряжение», «Заметки».
  Владелец листа и мастер входят в правку кнопкой **«Править»** (без заливки); кнопки
  «Сохранить» нет — ОЗ, характеристики, монеты и остальные поля сохраняются сами, после
  паузы в вводе (в шапке видно «Сохранено в ЧЧ:ММ»). Выход — «Готово». Кнопка
  «Повысить уровень» — с заливкой. Остальные смотрят лист в режиме чтения.
- **Каталоги с галочками.** Особенности, изъяны, навыки и знания выбираются списками с
  прокруткой и короткими описаниями; у навыков и знаний — ранг I–V и минимум характеристики.
- **Генерация характеристик.** Три способа из книги: «Суровый жребий» (3d6 по порядку),
  «Раскладка» (3d6×7, худший отбросить) и «Героический жребий» (4d6 с отбросом меньшей).
- **Происхождение.** Шесть народов Кас-Хатара с модификаторами характеристик, языками и
  культурным кодом: один конкретный навык и два знания. Выбор сразу добавляет дары и их
  стартовое снаряжение в рюкзак; смена народа снимает старые.
- **Навыки и знания отдельно.** Недоступные по минимуму характеристики не показываются;
  у выбранных — ранг I–V и пометка «от происхождения». Каждый навык и знание даёт
  подобранный стартовый набор в рюкзак.
- **Снаряжение по слотам.** Каталог предметов с описаниями; лимит слотов равен Силе.
  В руках — 1 оружие + щит, 2 одноручных или 1 двуручное; доспех один и не занимает руки;
  не больше четырёх предметов без слотов. Предметы двигаются между руками и рюкзаком;
  всё, что не помещается в слоты, подсвечивается красным.
- **Монеты в рюкзаке.** Отдельного поля денег нет: монеты — строка инвентаря, и вес у
  каждого металла свой — медь 200 монет на слот, серебро 150, золото 100, платина 50.
  Вес написан в описании номинала прямо в блоке монет; общий счёт слотов — по металлу.
- **Портрет.** Загрузка jpg/png (и любого формата, который читает браузер), обрезка в круг
  с перетаскиванием и ползунком размера; в карточке — круг, по клику открывается полная
  картинка. Хранится в листе как сжатый data URL.
- **Часы кампании над картой.** На «Столе» над картой — дата по календарю Кас-Хатара, день
  шестицы, время и часть суток. Погода идёт одной строкой со значками: температура, ветер со
  стрелкой и скоростью, облачность с осадками в миллиметрах, фазы обеих лун. По клику строка
  раскрывается: описание погоды, что она значит за столом, климатическая норма суток
  (ночной минимум и дневной максимум), подробности по ветру и осадкам. Игровые часы идут в
  темпе реального времени; мастер двигает их кнопками (−1 ч, +1 ч, +8 ч, +1 день), ставит на
  паузу и перебрасывает погоду. Всё это хранится снимком в комнате, поэтому у всех совпадает;
  запись в Redis — только на действие мастера.
- **Календарь, климат и небо.** `lib/calendar.ts` — 12 месяцев по 30 дней с ассирийскими
  именами (на базаре «Нисан», в грамотах «Нисану»), пятеро Немых дней, шестидневная неделя,
  12 праздников, знаки Небесного Круга (гороскоп), небесные тела и погода. Климат — резко
  континентальная степь: средняя температура и суточный размах по месяцам, осадки в
  миллиметрах, свой набор погод для тёплой и холодной половины года (ливни с градом, суховеи,
  пыльные бури, буран, стужа, оттепель, возвратные заморозки). В книгах сеттинга этого нет —
  есть только счёт «по событиям», поэтому календарь придуман и выгружен в базу:
  `npm run calendar:book` пишет `../books/Vtorye/Кас-Хатар_Календарь_и_небо.md`.
- **День рождения и натальная карта.** На вкладке «Основное» — день и месяц рождения;
  лист показывает знак, стихию Порядка/Равновесия/Хаоса, покровителя, положение обеих лун,
  ближайший праздник и маленькую выгоду знака. Дата лежит в `fields.birth` («дд.мм») и
  записывается, только когда выбраны и день, и месяц; пока вторая половина пуста, набранное
  остаётся в полях, но в лист не пишется.
- **Бросок возраста.** На вкладке «Характеристики»: два d6 на десятки и d10 на единицы
  (21–130 лет). Возраст даёт поправки к характеристикам — они применяются один раз, видны
  на листе и снимаются кнопкой «Снять».
- **Стартовые монеты.** На вкладке «Снаряжение»: максимальный модификатор характеристики
  × d6 × 10 золотых денариев, с показом формулы и суммы.

## Схема правил

Состав листа описан в одном файле — `lib/rules.ts`: характеристики, производные числа,
навыки и знания, особенности и изъяны, предметы, доспехи и щиты. Короткие описания для
каталогов — в `lib/notes.ts`. Форма и карточка строятся из этих массивов, поэтому под свою
редакцию правил достаточно поправить значения и формулы, не трогая компоненты.

Что уже сведено с «Книгой игрока» (`../books/Vtorye/ВТОРЫЕ_Книга_игрока.md`):

- **1.1, 1.5** — шесть характеристик 3–18, модификатор `(значение − 10) / 2`, три способа
  генерации, бонус испытаний +2/+3/+4, ОЗ `8 + Тел`, КБ `доспех + Ловкость (с пределом) + щит`.
- **1.2** — шесть происхождений: модификаторы, языки и культурный код из одного навыка и
  двух знаний; при выборе сразу выдаются стартовые наборы этих навыков и знаний.
- **1.3** — 25 особенностей и 15 изъянов с описаниями; на листе одна особенность и один изъян.
- **1.4.5** — стартовые наборы подобраны для всех 83 навыков и знаний и лежат в `STARTER_KITS`.
- **6.5–6.7** — 10 боевых навыков, 50 небоевых и 23 знания с минимумами, пометкой ★ и
  короткими описаниями; уточнения вроде «Язык: шуари» распознаются; недоступные по
  минимуму не показываются.
- **7.3–7.5** — 95 предметов плюс монеты: оружие, доспехи, щиты, свет и припасы; слоты,
  цены, описания, `twoHanded` для двуручного оружия.
- **1.4** — предыстории и мировоззрение не выбираются: это примеры и концепция из книги.
  Игрок сам отмечает навыки и знания, а монеты лежат в рюкзаке (100 шт. = 1 слот).

Если правило меняется в книге, синхронизируйте массивы и формулы в `lib/rules.ts`,
описания — в `lib/notes.ts`, и покройте изменение тестом в `tests/rules.test.mjs`.

### Выгрузка каталогов в Markdown

Полный список происхождений, навыков, знаний, особенностей, изъянов и снаряжения
собирается из тех же массивов одной командой:

```bash
node tools/export-rules.cjs        # → ../books/Vtorye/ВТОРЫЕ_Каталоги.md
node tools/export-rules.cjs ../мой.md   # или в свой файл
```

Файл `ВТОРЫЕ_Каталоги.md` — снимок данных для вычитки и сверки с книгой.
Источник правды остаётся в `lib/rules.ts` и `lib/notes.ts`: правите код — повторяете выгрузку.

В шапке каталога и в шапке «Кас-Хатар_Календарь_и_небо.md» стоит версия VTT, из которой
они выгружены. `npm test` сверяет обе шапки с `package.json` (`tests/catalog-export.test.mjs`),
поэтому после подъёма версии выгрузки нужно повторить: `npm run rules:books` и
`npm run calendar:book`. Если папки `books/` рядом с репозиторием нет (чистый клон, Docker),
проверки пропускаются.

Строка «Состав: …» в шапке каталога — счётчики происхождений, боевых и небоевых навыков,
знаний, особенностей, изъянов, предметов и видов монет. Тот же тест сверяет их с массивами
`lib/rules.ts`, поэтому правка каталога без пересборки не проходит незамеченной, даже если
версия в `package.json` не менялась. Ловятся изменения количества; переименование или
правка описания при тех же числах — нет, для этого есть `tools/sync-books.cjs` и вычитка.

### Книги и каталог совпадают дословно

Обе книги «Вторые» берут таблицы снаряжения из каталога, а не хранят свою копию.
После правок в `lib/rules.ts` достаточно одной команды:

```bash
npm run rules:books     # = export-rules.cjs + sync-books.cjs
```

`tools/sync-books.cjs` вставляет таблицы монет, доспехов, щитов, одежды, оружия,
снаряжения, животных, транспорта и наёмников в разделы 2.3–2.6 книги правил и
7.3–7.6 книги игрока, дополняет разделы про монеты и нагрузку, выравнивает
минимумы навыков (Грамота и Верховая езда — 10, Природа и звери — 12) и в конце
проверяет, что каждая строка таблицы каталога присутствует в обеих книгах.
Если расхождения есть, команда завершается с кодом 1 и печатает список.
Если в папке книг нет `ВТОРЫЕ_Каталоги.md`, скрипт тоже завершается с кодом 1,
но вместо стека `ENOENT` пишет путь, по которому искал каталог, и напоминает
про `VTT_BOOKS_DIR` и пересборку `node tools/export-rules.cjs`.

Скрипт умеет работать не только с рабочими книгами: переменная `VTT_BOOKS_DIR`
задаёт другую папку с `ВТОРЫЕ_Каталоги.md` и двумя книгами. На этом построен
`tests/sync-books.test.mjs` — он копирует книги во временную папку и проверяет,
что второй прогон ничего не меняет (идемпотентность), что пропавший раздел ломает
сверку и даёт код 1, что откатившиеся минимумы навыков (Грамота и Верховая езда — 10,
Природа и звери — 12) выравниваются обратно, что устаревший раздел «2.7. Уточнения
каталогов» вырезается целиком, не задевая соседние, что без блока в каталоге
скрипт падает с его именем, не успев переписать книги, и что без самого каталога
ошибка называет папку книг и `VTT_BOOKS_DIR`, а не печатает стек чтения файла.
Рабочие файлы тест не трогает.

Старый лист (Тело / Реакция / Разум / Воля / Эмпатия / Тень, Здоровье и Стресс)
читается по совместимости: ОЗ подхватывается из прежнего ресурса `health`, навыки —
из поля `level`, старые `money`, доспех и щит переносятся в монеты и инвентарь; при первом
сохранении лист переводится на новую схему.

### Календарь и небо

Календарь, праздники, знаки Небесного Круга, луны и погода живут в `lib/calendar.ts`.
В книгах сеттинга есть только счёт «по событиям», так что это дополнение для стола.
Выгрузка в базу знаний — одной командой:

```bash
npm run calendar:book   # tools/export-calendar.cjs
```

Она пишет `../books/Vtorye/Кас-Хатар_Календарь_и_небо.md` (приложение к путеводителю).
Правите текст — правьте `lib/calendar.ts` и повторяйте выгрузку, иначе лист персонажа
и книга разойдутся.

Проверить, не разошлась ли книга с кодом, можно без записи:

```bash
npm run calendar:check   # node tools/export-calendar.cjs --check
```

Сверка собирает текст заново и сравнивает его с файлом на диске: если файла нет или он
отличается, печатается первая разошедшаяся строка (что стоит в книге и что в
`lib/calendar.ts`) и скрипт выходит с кодом 1, ничего не записывая. Переменная
`VTT_BOOKS_DIR` задаёт другую папку книг — на этом построен `tests/export-calendar.test.mjs`.

В шапке книги стоит версия VTT, из которой она выгружена: `Выгрузка из VTT Poison Press
vX.Y.Z (файл lib/calendar.ts)`. `npm test` сверяет её с `package.json`
(`tests/catalog-export.test.mjs`), так что после подъёма версии книгу нужно пересобрать
той же командой.

## Локальный запуск

```bash
npm install
npm run dev
# http://localhost:3000
```

Проверки:

```bash
npm run typecheck   # tsc --noEmit
npm test            # node --test tests/dice.test.mjs tests/rules.test.mjs tests/calendar.test.mjs tests/characters.test.mjs tests/youtube.test.mjs tests/catalog-export.test.mjs tests/export-calendar.test.mjs tests/sync-books.test.mjs
npm run build       # production-сборка, как на Vercel
```

`npm test` импортирует `lib/dice.ts`, `lib/rules.ts`, `lib/calendar.ts`, `lib/characters.ts`
и `lib/youtube.ts` напрямую, поэтому нужен
Node 22.18+ (встроенное стирание типов); по этой же причине `lib/characters.ts` подключает
`./rules.ts` с расширением (в `tsconfig.json` включён `allowImportingTsExtensions`). `tests/catalog-export.test.mjs` читает
`../books/Vtorye/ВТОРЫЕ_Каталоги.md` и `Кас-Хатар_Календарь_и_небо.md` с диска, сверяет
`Выгрузка из VTT Poison Press vX.Y.Z` в шапках обоих файлов с `package.json`, а строку
«Состав: …» каталога — со счётчиками массивов `lib/rules.ts`;
`tests/export-calendar.test.mjs` гоняет `tools/export-calendar.cjs` на временной папке книг
через `VTT_BOOKS_DIR`: первый прогон собирает книгу заново, второй ничего в ней не меняет
(идемпотентность), `--check` падает с кодом 1 и печатает разошедшуюся строку, если книгу
поправили мимо `lib/calendar.ts`, и не создаёт файл, если книги нет; на рабочей книге базы
та же сверка проверяет, что она собрана из текущего `lib/calendar.ts`;
`tests/sync-books.test.mjs` гоняет `tools/sync-books.cjs` на временной копии книг
(идемпотентность, негативная ветка сверки, минимумы навыков, удаление раздела 2.7,
ошибка на пропавшем блоке каталога и ошибка без самого каталога). Если книг или каталога рядом нет,
эти тесты помечаются пропущенными. На Vercel тесты не запускаются — только сборка.

Без переменных окружения комнаты живут в памяти процесса — удобно для разработки,
но данные пропадают при перезапуске и не делятся между инстансами.

## Хранилище и деплой на Vercel

На Vercel серверные функции не хранят состояние между вызовами, поэтому нужен Redis.
Поддерживается любой Upstash Redis (Vercel KV, Marketplace или нативный Upstash) —
достаточно REST-переменных, транспортные пакеты не нужны:

```
UPSTASH_REDIS_REST_URL=...
UPSTASH_REDIS_REST_TOKEN=...
# либо, если интеграция даёт именно эти имена:
KV_REST_API_URL=...
KV_REST_API_TOKEN=...
```

`UPSTASH_*` имеет приоритет над `KV_REST_API_*`. Если в проекте остались старые
`KV_REST_API_*` от выведенного Vercel KV, их лучше удалить: иначе можно получить
403 от старой базы. URL и токен всегда должны быть **от одной базы**, а токен —
полный **REST Token**, не **Readonly Token**. Значения из `.env` не должны содержать
кавычек и пробелов.

Порядок:

1. Импортируйте репозиторий в Vercel (Framework Preset определится как Next.js,
   команды сборки менять не нужно).
2. В проекте Vercel добавьте интеграцию Redis (Upstash) — переменные подставятся сами,
   либо добавьте их вручную в Settings → Environment Variables.
3. Задеплойте заново: изменения env не применяются к уже собранному деплою.
4. Откройте корень сайта, нажмите «Создать комнату», скопируйте ссылку.

Без Redis приложение тоже поднимется, но на Vercel комнаты будут «пропадать» между
запросами — это режим для локальной разработки.

### Проверка хранилища

`GET /api/health` показывает, какой режим включён, и пингует Redis через REST.
`GET /api/health?deep=1` дополнительно делает `SET` + `DEL` тестового ключа — так
видно, что токен не readonly:

```json
{
  "ok": true,
  "deep": true,
  "storage": {
    "mode": "redis",
    "reachable": true,
    "latencyMs": 42,
    "source": "upstash",
    "host": "eu1-xxx.upstash.io",
    "canWrite": true,
    "status": 200,
    "error": null
  },
  "checkedAt": 1793004098827
}
```

`mode: "memory"` — переменные окружения не подхватились; `reachable: false` — Redis
настроен, но не отвечает; `canWrite: false` — токен только для чтения. Эндпоинт отдаёт
`503`, если Redis недоступен или не может писать. Тот же статус виден в панели стола
строкой «Хранилище: Redis · N мс».

Если в `error` приходит `This database has reached current Fixed plan limits`, ключи
верны, но закончился лимит тарифа Upstash. Откройте Upstash Console → базу →
**Billing/Plan** → **Upgrade** или **Enable auto upgrade**; передеплой не нужен.

### Регион функций

Регион функций Vercel выбирается отдельно от региона базы: новый проект по умолчанию
собирается в `iad1` (Вашингтон), даже если база Upstash лежит во Франкфурте. Каждый
запрос к Redis тогда идёт через Атлантику (~100 мс). Чтобы этого избежать, выставьте
Settings → Functions → Function Region в регион базы (`fra1` для Frankfurt) и
передеплойте проект.

### Про обновление данных

Состояние комнаты лежит в одном ключе `poison-press:room:<КОД>` (JSON, TTL 30 дней).
Клиент **не опрашивает базу по таймеру**: `/api/rooms/<КОД>/state` вызывается после своих
действий (сообщение, правка листа, карта, музыка, вход), при возврате на вкладку, при
переключении вкладки и по кнопке `⟳` в шапке. Присутствие тоже обновляется действиями —
без отдельного «пульса». Побочный эффект: чужие изменения видно не мгновенно, а после
своего следующего действия или обновления — зато нет постоянного трафика в Redis.

Сколько это стоит, видно в дебаг-панели мастера внизу страницы: запросы и байты за сессию
и за день, разбивка по адресам, режим хранилища и пинг. Линии карты хранятся в том же JSON
комнаты (до 200 линий по 600 точек), поэтому после сессии их можно очистить кнопкой мастера.
Сами YouTube-плееры работают в браузерах игроков, сервер хранит только ссылки, состояние
play/pause и громкость трека.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/rooms` | создать комнату, вернуть код |
| GET | `/api/health` | режим хранилища (Redis/память), пинг Redis и задержка |
| GET | `/api/rooms/[code]/state?since=<seq>` | снимок комнаты и новые сообщения |
| POST | `/api/rooms/[code]/join` | вход/возврат игрока по имени |
| POST | `/api/rooms/[code]/heartbeat` | присутствие (старый путь; клиент теперь обновляет `lastSeen` действиями) |
| POST | `/api/rooms/[code]/messages` | сообщение (бросок считается на сервере) |
| DELETE | `/api/rooms/[code]/messages/[id]?actor=` | удалить сообщение: своё или любое (мастер) |
| PATCH | `/api/rooms/[code]/players` | профиль: имя, цвет, привязанные персонажи |
| DELETE | `/api/rooms/[code]/players?actor=&target=` | убрать игрока из-за стола (мастер) |
| POST | `/api/rooms/[code]/characters` | создать персонажа |
| PATCH | `/api/rooms/[code]/characters/[id]` | правка листа |
| DELETE | `/api/rooms/[code]/characters/[id]?actor=` | удалить лист (владелец или мастер) |
| PATCH | `/api/rooms/[code]/characters/[id]/players` | назначить лист игрокам (обратная сторона привязки) |
| POST | `/api/rooms/[code]/map` | рисунки, ластик, метки и очистка карты |
| POST | `/api/rooms/[code]/music` | добавить, играть, пауза, громкость трека |
| POST | `/api/rooms/[code]/world` | часы кампании и погода: `set`, `advance`, `running`, `weather` (мастер) |

## Если появилось «Failed to fetch»

Это сообщение браузера значит, что запрос **не дошёл до сервера** (или ответ не вернулся).
В интерфейсе теперь пишется «Нет связи с сервером (Failed to fetch)». Что проверить по порядку:

1. **Сеть.** Пропал Wi-Fi, VPN, мобильный интернет — обновите страницу и нажмите `⟳` в шапке.
2. **Свой сервер выключен или перезапускается.** На VPS: `systemctl status vtt`,
   логи `journalctl -u vtt -n 50`. На Vercel: проект → Deployments, не идёт ли пересборка
   и не приостановлен ли проект из-за лимитов.
3. **Страница по http, а API по https** (или наоборот) — mixed content браузер режет.
   Схема у страницы и у API должна быть одна.
4. **Блокировщики и прокси.** uBlock/AdGuard/корпоративный прокси иногда режут `POST`
   на `/api/rooms/...` — проверьте в инкогнито без расширений.
5. **Upstash исчерпал лимит** — тогда ответ приходит, но с ошибкой хранилища: смотрите
   «диагностика мастера» внизу стола или `/api/health?deep=1`.
6. **Холодный старт.** Первый запрос после простоя может отвалиться по таймауту — повторите.

Как отличить одно от другого: в дебаг-панели мастера у такого запроса статус `0` —
это «до сервера не достучались», а не ответ сервера с ошибкой.

## Известные ограничения

- Нет авторизации: кто знает ссылку и имя — тот за столом. Имя и есть идентичность,
  поэтому под чужим именем можно войти (как в дружеском чате). Удаление игрока мастером
  убирает его из списка, но вернуться по той же ссылке он сможет.
- Лимит груза и рук проверяется в интерфейсе; сервер нормализует данные, но не запрещает
  сохранение перегруза (нужно для переноса старых листов).
- Портрет хранится в листе как сжатый data URL (до ~260 КБ обрезанный и ~540 КБ полный);
  это увеличивает размер комнаты в Redis. Очень большие фото браузер сжимает сам.
- Обновление вместо WebSocket: без фонового опроса чужие изменения приходят после вашего
  действия, при возврате на вкладку или по кнопке `⟳`. Для «живого» стола этого мало, зато
  расход запросов к Redis минимальный.
- Одновременные записи в Redis из разных инстансов не блокируются (блокировка только
  внутри процесса) — для стола на несколько человек этого достаточно.
